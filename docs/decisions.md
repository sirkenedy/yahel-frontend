# Decisions

Append only. Each entry says what was decided, why, and what was rejected. Design-system decisions are in `design-system/docs/decisions.md`.

| ID | Date | Decision | Why | Rejected |
|---|---|---|---|---|
| F-1 | 2026-11-12 | React 19, TypeScript, Vite, client-rendered. One app per product in a pnpm monorepo with Nx as task runner. | Every app sits behind sign-in and is highly interactive; server rendering adds cost without benefit. One app per product keeps bundles and failures separate. | Next.js; one large app; runtime micro-frontends. |
| F-2 | 2026-11-12 | TypeScript pinned to 5.9. | TypeScript 7 broke the API type generator (needs the 5.x compiler API) and is outside the range the lint tooling supports. | Latest TypeScript. Revisit when `openapi-typescript` and `typescript-eslint` support it. |
| F-3 | 2026-11-12 | Package boundaries are enforced by `scripts/check-boundaries.mjs`, not by Nx's lint rule. | In testing, the Nx rule skipped itself with a warning when its project graph cache was missing. A guard that can silently not run is not a guard. The script is deterministic and was tested against planted violations. | `@nx/enforce-module-boundaries`. |
| F-4 | 2026-11-12 | Access token in memory only; refresh token in session storage. | The backend returns both tokens in the response body. Memory-only access tokens limit what script injection can steal; session storage limits the refresh token to the tab's lifetime. | Local storage (survives longer, larger theft window). **Better, needs backend work:** deliver the refresh token as an `HttpOnly`, `Secure`, `SameSite` cookie so no script can read it. Until then a successful script injection could steal a refresh token. |
| F-5 | 2026-11-12 | Response types are hand-written in `packages/api-client/src/types.ts`. | The backend's OpenAPI description declares request bodies but no response bodies. | Guessing shapes; skipping types. **Needs backend work:** add response decorators so these can be generated. |
| F-6 | 2026-11-12 | Browser tests run against a mock backend in `e2e/support/api.ts`. | Fast, deterministic, no database needed in CI. | Running the real backend in CI for every pull request. A staging smoke test against the real backend is still needed (roadmap). |
| F-7 | 2026-11-12 | Mobile Safari (WebKit) tests run in CI only by default. | The current WebKit build does not run on the development machine's macOS version. Locally: `E2E_WEBKIT=1 pnpm e2e` on a supported system. | Dropping WebKit coverage. |
| F-8 | 2026-11-12 | The design system moved into this repository: tokens and UI code as packages, written docs under `design-system/`. This copy is canonical. | Agents here need the specs and tokens beside the code they govern. | Keeping it in the backend repository. The copy there should be removed to avoid two sources of truth. |
| F-9 | 2026-11-12 | Plain CSS on tokens; no CSS-in-JS, no utility framework. | The token layer already is the abstraction, and a check proves every value is a token. | Tailwind; styled-components. |
| F-10 | 2026-11-12 | Agents merge through GitHub auto-merge behind three required checks; no agent holds merge permission. | The owner asked for unattended merging once QA, desktop and mobile tests, all other tests and security checks pass with reviewer approval. Auto-merge makes GitHub, not an agent, the one that decides the checks are green. | Agents calling merge directly; requiring a human approval on every pull request. |
| F-11 | 2026-11-12 | The accessibility scan excludes React Aria's hidden live-announcer node. | After a pending button unmounts, the announcer keeps a reference to its label, which the scanner reports. It is invisible library plumbing, not product markup. | Disabling the rule everywhere. |
| F-12 | 2026-11-12 | Translation is not set up yet; strings are collected in per-feature `messages.ts` files. | Keeps every string in one place per feature so a translation library can be added without touching components. | Adding a translation library before there is a second language. |
| F-13 | 2026-11-12 | The product name is **Yahel**. | Decided by the owner. The interface, docs and design system in this repository now say Yahel. The backend's API title still says "WorkSync Space", so the committed API snapshot does too; design tokens keep the `--ws-` prefix, which is an internal name and not shown to anyone. | Keeping "WorkSync Space". |
| F-14 | 2026-11-12 | No AI attribution anywhere: no `Co-Authored-By` trailer and no "Generated with" line in commits or pull requests, from people or agents. | Decided by the owner. `scripts/check-attribution.mjs` fails CI if one appears. | Default tool attribution. |
| F-15 | 2026-11-12 | The backend announces API changes to this repository (event plus summary, and an issue when breaking); the design system is read by the backend from here. | Each side has one source of truth it owns and a push notice to the other, instead of copies that drift. | Copying the design system into the backend; polling a deployed backend only. |
| F-16 | 2026-11-12 | Agent reviews run on the author's machine before a pull request opens (`/pre-pr`), not in GitHub Actions. A `Review receipt` check proves all four reviewers approved the exact change. In-CI agents remain available but are off by default. | The owner has a Claude subscription, not an API key, and wants pull requests opened only for changes that already passed review. It is also cheaper and faster: problems are fixed before CI runs. | Requiring an API key in the repository. |
| F-17 | 2026-11-12 | Review is proportionate: three tiers set by the changed paths; only blockers stop a change; majors become a follow-up issue; one fix round; reviewers carry across rounds, report everything in the first, and cannot block on unchanged code in the second (security and data loss excepted). | Decided by the owner after the first end-to-end test took a small feature through four review rounds. Any of four reviewers could veto on anything above a note, and a missing test for working behaviour blocked like a defect. | Four reviewers with zero majors for every change (the original bar). The cost accepted: some imperfect changes merge with follow-up issues open. |
| F-19 | 2026-11-12 | The public website is its own app, `apps/website`, of a new package kind `type:site` that may depend only on `type:ui` and `type:tokens`. Its reusable pieces (`Reveal`, `SiteBar`, `SiteMenu`, `LinkButton`) live in `@yahel/ui` with their CSS in a separate `@yahel/ui/site.css`. It will be prerendered to static HTML, which amends F-1 for this app only; until then it carries `noindex`, because its pages still show marked placeholders. Bundle budget: entry 100, total 160, CSS 14 kB gzip. Scale tokens added for it: `duration.reveal-move`, `duration.stagger`, `radius.3xl`, `space.72/88/112`, `size.site-content`, `size.site-bar`, `size.site-bar-compact`, `size.site-cta`, `size.reveal-rise`, `breakpoint.site-nav`, and a `display` type group (`xl`, `l`, `title`, `heading`, `lead`, `body`, `label`, `eyebrow`) that does not shrink on pointer devices. The CSS token check now also scans every app's CSS. Motion is CSS transitions on tokens; the top bar compacts by transform, not height; pages cross-fade through the View Transitions API where it exists. The phone menu's dialog code loads on demand, to keep the entry inside its budget. The router writes two things to session storage, which rulebook 4.1 now permits for this app alone: `tsr-scroll-restoration-v1_3`, the scroll offsets of visited pages keyed by history entry or page address (so Back returns to where the reader was), and `tanstack_router_reload:<error message>`, a marker it sets when a page chunk fails to load and it reloads once. Neither holds anything about a person; a browser test asserts the website's storage holds nothing else. A production build served anywhere but this machine refuses to start unless `VITE_APP_URL` is an https address; variables are read from the repository's root `.env`. | The site is public and sits on the root domain: it must not wait on a session, and nothing should be able to add the API client or session to it by accident. F-1 chose client rendering because every app sits behind sign-in; this one does not, and crawlers and link previews need the content in the HTML. Canvas pixel values are pictures of tokens, so the missing ones were added instead of written raw. | Routes inside the shell (couples a public deployment to session start-up); reusing `type:app` (nothing would stop `@yahel/auth` being added); a motion library (30 to 60 kB for six transitions); CSS scroll-driven animations (not in Safari); animating the bar's height (shifts layout under a sticky element); site CSS in `styles.css` (charges every product app for marketing CSS); Google Fonts (third-party origin, rulebook 4.6). |

| F-20 | 2026-11-12 | The public website is prerendered, which amends F-1 for `apps/website` only. **Build.** Three steps: the browser build; a second build of the same routes for Node (`vite build --ssr src/prerender.tsx`, written under `node_modules/.prerender`, outside `dist`, and removed afterwards); and `scripts/prerender.mjs`, which draws `/`, `/about` and `/careers` with React's `renderToString` into the built `index.html` and writes `index.html`, `about.html` and `careers.html`. **App address.** The written pages carry the account links for every reader, before any script runs, so the build is where the address is refused: it exits non-zero and writes no page unless `VITE_APP_URL` is https. A build that is not deployed says so with `WEBSITE_LOCAL_BUILD=1` on the command line (`pnpm build`, and so `pnpm verify` and CI's build for the browser tests, set it; the website's own `build` script, which a deployment runs, does not). Both variables are inputs of the build cache. A local build served from another host still refuses to start in the browser and empties the root, so its links are not left on screen. **Taking the page over.** Each root is marked with the address it was drawn for (`data-page`). `public/motion-gate.js`, a plain script in the head, decides once the HTML is parsed whether that is this address (it treats `/careers.html` as `/careers` and corrects the address bar) and marks the root; the page's script hydrates only then, and otherwise draws afresh, so an unknown address that a host answers with the home page still shows "Page not found", and a link into a section is drawn with its own bar state. **Content before the script.** The same head script switches on the hidden starting state of scroll reveals before first paint, and on a page written for this address it brings blocks in itself as they are scrolled to, on the same terms as `Reveal` (12% in view, 8% up from the bottom): content never waits for the page's script, and hydration keeps what is already shown. A page that will be drawn afresh stays hidden for at most `duration.loop` (1400 ms) and is then shown as written. With JavaScript off the script never runs and everything is visible. **The bar without scripts.** The head script also sets `data-scripts`; without it the Menu button is not shown and, below 860, the bar's links take a row of their own. It is taken back when a script cannot be fetched. **A page whose code does not arrive.** On a direct visit the written page is left as it is, not hydrated. On a move between pages the router reloads the address once, which leaves the written page; a second failure shows a message in the page, with the bar and footer, a link that loads the address again and the way home. **Tabs.** The team filter is `SegmentedTabs` on React Aria Tabs; it reaches the browser in the Careers page's own chunk, not the entry. Its arrow keys follow the page's `dir`, not the browser's language. | F-1 chose client rendering because every app sits behind sign-in. This one is public: readers without scripts, crawlers and link previews need the content in the HTML. Once the links are in the HTML, a check that runs in the browser is too late, and a warning in a build log is not a check. | TanStack Start, Next or Astro (a framework and second toolchain for three static pages); the router's own server-rendering handlers (they render a whole document and send router state in inline scripts, for loaders this site does not have); `about/index.html` (`vite preview`, which the browser tests use, serves `/about` from `about.html` only; revisit with the host, O-4); an inline script for the gate or for scroll restoration (a later Content Security Policy would need to allow it); top-level `await` in the entry (the bundler then moves shared code out of the entry file, which would have hidden it from the entry budget); inferring a local build from the host or from the address (the mark must be explicit); uncovering the written page when the page's script throws (it showed a page whose configuration had been refused); a timer alone for slow scripts (content in view would still wait for it). Not done: a `404.html`, which depends on the host. |
