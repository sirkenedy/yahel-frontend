Onboarding · Feedback states

Every message says what happened, what’s safe, and what to do next.

Nine patterns cover every input state, error, warning, success and wait in sign-in and sign-up. Pick the one closest to the problem: a field before a banner, a banner before a dialog, a dialog before a full page. Each is shown in light and dark.

1Say what happenedPlain words, no codes, no blame. “That code didn’t work”, not “Invalid OTP”.
2Say what’s safePeople worry about losing work. Tell them: “Nothing you typed was lost.”
3Offer one way forwardEvery message ends in an action or a time: “Try again”, “in 0:24”.
4Never colour aloneEvery tone pairs its colour with an icon and words, in light and dark.

PATTERN 1Input statesEvery text field has the same seven states. Colour is never alone: errors add a thicker border, an icon inside the field and a message; the label turns red too.
  • Typing for the first time never shows red.
  • Leaving a field you typed in checks it.
  • While fixing a field, it re-checks on every key and turns green the moment it’s right.
  • Continue checks everything, moves focus to the first problem and, with two or more, lists them in a banner.
  • Green ticks only on fields with a format to get right (email, phone, domain, password), never on names.

PATTERN 2Field messageThe problem belongs to one field: a wrong password, a taken address, a code that didn’t work. Fix it where the person is looking.
  • Shows after Continue, never while typing (except live checks like address availability).
  • Says what’s wrong and how to fix it, in one sentence.
  • Adds one link when there’s a better path: “Create a Yahel account instead”.
  • Counts down tries for codes: “4 tries left”.

PATTERN 3BannerThe problem is about the whole step, not one field: offline, a server error, a domain someone else claimed, the last try before a pause.
  • Sits under the heading, above the form, so it’s read first.
  • Two or more field errors on Continue become one summary banner: “2 things to fix before you continue”.
  • Title says what happened. Body says what’s safe and what to do.
  • At most two actions, written as verbs.
  • Error and warning banners are announced to screen readers.

PATTERN 4ToastSomething worked, or a small change happened, and the person doesn’t need to act: a code was sent, something was copied, the connection came back.
  • Bottom centre, clear of the header and the form; above the keyboard on phones.
  • Stays 4 seconds. Hovering pauses it; the thin bar shows time left. The × closes it.
  • Never the only place an error is shown.
  • Short: one line, past tense.
New code sent. Older codes no longer work.

PATTERN 5Connection barThe device lost its connection. It stays until the connection is back, then a toast says so.
  • Full width above the header, pushes the page down instead of covering it.
  • Says what’s safe first: what you typed stays on this device.
  • Pressing Continue while offline shows the offline banner; nothing is lost.

PATTERN 6Busy button and slow hintA step is waiting on the server. The button names what’s happening; after 1.2 seconds a quiet line explains a slow connection.
  • The button can’t be pressed twice while busy.
  • Labels: Checking…, Signing in…, Verifying…, Sending code…, Saving….
  • No spinner-only screens for waits under 2 seconds.

PATTERN 7CountdownThe person must wait before trying again: resending a code, or after too many requests.
  • Shows the time left in the control itself: “Send a new code in 0:24”.
  • Uses tabular numbers so the text doesn’t jump.
  • Turns back into a link when the wait is over.

PATTERN 8DialogSomething outside this step needs a decision before anything else: the session ended, or we signed the person out for security.
  • Rare. Never for form errors.
  • Always says nothing was lost, when that’s true.
  • One main action; a second only if it’s a real alternative.
  • Bottom sheet on phones.

PATTERN 9Full pageThe person can’t continue at all from here: account turned off, workspace paused, link expired, sign-in paused, server down.
  • Replaces the step, keeps the header and footer.
  • Big calm icon, plain heading, what’s safe, one way forward.
  • Error pages show a reference the person can quote to support.
