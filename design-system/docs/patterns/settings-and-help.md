# Settings and help

## Settings

- **Fewer settings.** Good defaults beat options. Add a setting only when people genuinely differ.
- **Three places, clearly separated:** account settings (identity, security, storage, notifications; apply everywhere), app settings (specific to Mail, Calendar and so on), and organisation settings (Admin console, administrators only).
- Frequently changed options live where they are used (view density in the view menu), not buried in settings.
- Each setting's label says what happens when it is on. A line of help text explains the consequence where it is not obvious.
- Changes apply immediately and are saved automatically, with a brief confirmation. Risky changes confirm first.
- Settings are searchable, and each has a link that opens it directly.
- A setting controlled by an organisation is shown locked, with "Managed by <organisation>", not hidden.
- Appearance follows the system by default. On web, where the browser cannot always supply them, settings offer light, dark and match system, plus increased contrast, reduced motion, reduced transparency and text size. Native iOS and Android builds follow the system's appearance and accessibility settings and do not repeat them.
- Never use a setting to ask for something that can be detected: language, region, time zone, theme, connected devices.
- On desktop, settings open with the platform's shortcut (Command-comma on Apple platforms). Settings reopen at the pane last viewed, and the title names the current pane.

## Help

- Help is in the same place in every app: the account or help menu, and `?` for keyboard shortcuts.
- First choice is help in context: clear labels, good empty states, tips at the moment of need.
- The help panel opens beside the work, not instead of it, and starts with articles about the current view.
- Contacting support carries context automatically (app, view, a reference code) with the person's consent, so they do not have to describe it.
- Tips are dismissible, never repeat once dismissed, and can be reviewed later.
- A tip covers one simple feature in one or two sentences, in direct wording, with no promotion. Anything that needs more than three steps is an article, not a tip.
- Tips have eligibility rules: never shown to someone who has already used the feature, and never more than one at a time.
- Help describes what a control does in this product. It does not explain how standard components work.
- Tooltips describe only the control pointed at, start with a verb, stay under about 75 characters, and use sentence case with no full stop. A control with a visible label gets a tooltip only if it adds something; it never repeats the label.

## Asking for feedback or ratings

- Never during onboarding, never in the middle of a task, never more than occasionally.
- Ask after a task completes successfully, make declining one tap, and do not ask again soon.
- A "Send feedback" entry is always available in the help menu.
